AI-Powered Cardiac Risk Assessment and Heart Failure Prediction

Extending IEEE SPIN 2024 with ensembles, a >20,000-patient cohort, and ECG interval screening

University project presentation · not a medical device

Problem

  • Cardiovascular disease: ~17.9 million deaths / year (WHO)
  • Heart-failure follow-up mortality is hard to triage from routine labs
  • Need an explainable research classifier — not a replacement for clinicians

Base paper — IEEE SPIN 2024

Sandilya, Pal, Dahiya, Dana — prognostic modeling as classification

  • UCI Heart Failure Clinical Records: 299 patients, 12 attributes + DEATH_EVENT
  • NB, KNN, DT, SVM, LR, RF, XGBoost · StandardScaler · 80/20 · GridSearch
  • Best: Random Forest 88.33% test accuracy
  • Top features: time, ejection fraction, serum creatinine, age

Dataset

Core 12: age, anaemia, CPK, diabetes, EF, high BP, platelets, creatinine, sodium, sex, smoking, follow-up time

ECG: PR, QRS, QT, QTc, ST, RR, P-wave, T amplitude, heart rate

Flags: prolonged QRS / QTc, ST shift, brady/tachycardia

Labels emphasize low EF, high creatinine, short time, older age (literature ranking).

Pipeline

Ingest / synthesize → validate → impute → StandardScaler → SMOTE (train) → classifiers + stacking → GridSearchCV → IEEE metrics + XGBoost importance → Streamlit inference

Metrics we report

Accuracy · Precision · Recall · F1 · MCC · PR-AUC · ROC-AUC

MCC and PR-AUC matter because death events are the minority class.

Software

  • OOP: DatasetHandler, DataPreprocessor, AdvancedHeartModels, HyperparameterTuner, AdminAuthManager

  • UI: clinician form, ECG visualizer, risk %

Limitations

  • 20k rows are synthetic — not a clinical trial
  • ECG plot is reconstructed from intervals, not a recorded 12-lead
  • Prototype ≠ certified medical device
  • Bone fractures supported: 0 — this is not an X-ray system (206 adult bones exist anatomically, none are inputs here)
